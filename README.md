# COLD CORE: 넷 시즈 — 디지털 프로토타입 (MVP)

> **저장소 메모**
> - `dist-single/cold-core-prototype.html` (약 90 KB)은 플레이테스트 산출물이라 일부러 커밋했다. 파일을 내려받아 브라우저로 열면 바로 실행된다 (`npm run build`로 다시 만든다).
> - `screenshots/`(약 6 MB, 22장)는 `npm run verify`가 다시 만들기 때문에 커밋하지 않았다.
> - 본문의 `../balance_results_v0.x.md` 보고서는 기획 문서 폴더에 있어 이 저장소에는 없다. 같은 수치의 원자료 `balance_results_v0.x.json`은 이 저장소에 있고, `npm run balance:v0x`로 다시 만들 수 있다.

기획서 `사이버펑크_해킹공성전_기획서.md` §15.2 MVP 범위를 구현한 플레이 가능한 프로토타입입니다. 백엔드·계정·외부 서비스 없음.

## 실행 방법
- **바로 플레이**: `dist-single/cold-core-prototype.html` 파일을 더블클릭 (서버 불필요, 단일 HTML).
- 개발: `npm install` → `npm run dev` (Vite 개발 서버)
- 빌드: `npm run build` (타입 검사 + `dist/` + 단일 파일 `dist-single/`)
- 테스트: `npm test` (vitest, 시뮬레이션 코어)
- 헤드리스 AI 대전 로그: `npm run sim` (환경변수 `SA`/`SB` = `balanced` | `raider`)
- 브라우저 검증: `npm run verify` (Chrome으로 단일 파일을 열어 플레이 + `screenshots/` 저장)
- 밸런스 측정: `npm run balance` (공성 압박 보정안 8조합 × AI 대전 800판/조합 → `../balance_results_v0.2.md`, `balance_results_v0.2.json`), `npm run balance:v03` (데이터 감속안 비교 → `../balance_results_v0.3.md`, `balance_results_v0.3.json`), `npm run balance:v04` (코어 브리치 데이터 비교 → `../balance_results_v0.4.md`, `balance_results_v0.4.json`, 진단 `npx vite-node scripts/diagnose-v04.ts`), `npm run balance:v05` (E1'·G1·G2 비교 → `../balance_results_v0.5.md`, `balance_results_v0.5.json`), `npm run balance:v06` (G2'·G3·C' 비교 → `../balance_results_v0.6.md`, `balance_results_v0.6.json`), `npm run balance:v07` (V1·V2·C''·AI 조기 공성 → `../balance_results_v0.7.md`, `balance_results_v0.7.json`), `npm run balance:v08` (기획 v0.3 확정 기준선 vs 하운드 5 CYC + 공성형 첫 파도 진단 → `../balance_results_v0.8.md`, `balance_results_v0.8.json`). 진단: `npx vite-node scripts/diagnose.ts`

## 화면 (4개)
타이틀 → 로드아웃(8슬롯 확인: 공격 4 + 방어 4 고정) → 매치 → 결과

## 조작
- **카드 드래그 → 노드에 드롭**으로 명령 추가 (또는 카드 클릭 → 노드 클릭). `Esc` = 선택 취소
  - ▲ 공격 프로그램(핑·오거·셰이드·사이펀): 대상 노드에 드롭 → 가장 가까운 내 릴레이에서 발사, 매 턴 자동으로 목표를 향해 이동
  - ■ 방어 ICE(벌워크·하운드·랜턴·허니팟): 내 노드에 드롭 → 이번 턴 정산 때 활성화(1턴 컴파일 지연)
- **노드 클릭** → 오른쪽 인스펙터: ICE 회수, 프로그램 철수/목표 변경, 수리, 핑 발사
- 왼쪽: 오버클럭 토글, 이번 턴 명령 목록(✕로 취소, 불가능한 명령은 빨간색 사유 표시)
- **명령 확정** 버튼 또는 `Space` → 양쪽 명령이 동시에 해결되고 아래 로그에 ①~⑦ 단계별로 설명됨 (`로그 크게 보기`로 확대)
- 핫시트: 확정 후 가림 화면이 뜨고 다음 플레이어가 "준비 완료"를 눌러야 화면이 보임. 상대의 명령·비공개 로그는 숨겨짐
- 타이머: 타이틀에서 켜기 (계획 20초 / 구축 60초, 만료 시 자동 확정). 기본 꺼짐
- **디버그 패널**(왼쪽 아래): 내/상대 HEAT +50, 상대 코어 -40, 내 데이터 +4, 20턴으로 이동, 기권 — 역추적·승리 화면을 빠르게 확인하는 용도

- **C. 서든데스**: T15부터 ⑤ 단계 끝에 양쪽 코어 고정 피해 6, 매 턴 +2. T15 계획 단계부터 안개 해제(허니팟 포함 모든 ICE 공개)
- 표시: 매치 상단 배지(이번 정산 유지비, 이번 턴 서든데스 피해, 안개 해제), 로드아웃·결과 화면 문구, 디버그 패널(ON/off 표시 + "유지비 시작으로"/"서든데스로" 이동 버튼). 효과는 모두 터미널 로그에 기록됨

## 데이터 감속안 v0.3 (실험용)
`SIEGE_PRESSURE`에 함께 들어 있고 A/B/C와 같은 방식으로 **타이틀 체크박스**에서 각각 독립적으로 켠다. 수치는 기획 예시값. 결정론·정수 연산 유지 (데이터 ×2 정수).
- **D1. 데이터 승리 기준 12 → 20점** (`dataWinRaised`). 상단 DATA 표시의 "목표"도 바뀜
- **D2. 중립 노드 데이터 누적 상한 6점/플레이어** (`neutralDataCap`). 플레이어별 `neutralData` 누적값으로 판정, 상한 직전에는 남은 만큼만 지급. 금고 사이펀 데이터는 상한과 무관
- **D3. 중립 데이터는 T6부터** (`neutralDataStartTurn`). 점령·중립 수입(CYC)은 그대로, 데이터 생성만 지연
- 중립 데이터 0.25 하향안은 구현하지 않음 (`neutralDataPerTurn` = 0.5 그대로)
- 표시: 상단 배지 "◇ 데이터 감속: 목표 20 · 중립 누적 x/6 · 중립 데이터 T6부터/ON", 로드아웃·결과·디버그 패널 옵션 목록. ⑦ 정산 로그에 "(원래 +1.5, 중립 데이터 상한 6점 도달 (D2))" / "(데이터 생성은 T6부터 (D3))" 형태로 기록
- ⚠ D1(20점)과 D2(6점)를 함께 켜면 한 플레이어가 얻을 수 있는 최대 데이터는 중립 6 + 상대 금고 2×4 = 14점이라 **데이터 승리가 불가능**하다 (이 시뮬레이션에는 코어 공격으로 얻는 데이터가 없음). 측정 결과는 `../balance_results_v0.3.md`

## 코어 브리치 데이터 v0.4 (실험용)
v0.4 측정 기준선 = A+B+C+D2+D3 (데이터 목표 12, D1 off). 타이틀 체크박스에서 독립적으로 켠다. 수치는 기획 예시값, 결정론·정수 연산.
- **E1. 코어 브리치 데이터**: 내 프로그램이 상대 코어 본체에서 실제로 깎은 HP를 누적(`coreDmgDealt`, 상대가 수리해도 줄지 않음)해 20마다 데이터 +2, 매치당 최대 +10. 데이터 승리에 포함되고 D2 중립 상한과 무관. ④ 교전 직후 지급, 로그 "코어 브리치 데이터 +2 (E1: …)"
  - [추정] 서든데스 고정 피해는 공격자가 없으므로 세지 않는다. 디버그 버튼 피해도 세지 않는다. 코어 위 ICE에 준 피해는 코어 본체 피해가 아니므로 세지 않는다
- **E2**: E1 + 중립 데이터 상한 6 → 4 (E2를 켜면 D2 체크 여부와 상관없이 상한 4)
- AI: E1/E2가 켜지면 **공성형만** 코어 집중(게이트 개방 후 오거 상한 +1, 노출도 여유 축소, 코어에 붙은 오거가 있으면 오버클럭). 다른 성향은 변경 없음
- 표시: 상단 배지 "◇ 코어 브리치 데이터: x/10 · 누적 코어 피해 y", 옵션 목록(로드아웃·결과·디버그)

## v0.5 옵션 (실험용)
타이틀 체크박스에서 각각 독립적으로 켠다. 수치는 기획 예시값, 결정론·정수 연산. v0.5 측정 기준선 = A+B+C+D2+D3+E2+E1'.
- **E1'. 브리치 데이터 → 시간 판정 전용**: E1/E2의 브리치 데이터를 데이터 점수(12점 승리)에 더하지 않고, 20턴 시간 판정 점수에만 더한다. 로그 "코어 브리치 데이터 +2 (E1': … — 20턴 시간 판정 점수에만 반영)"
  - E1'가 켜지면 20턴 판정 로그에 항목별 점수 표시: "A 7점 = 데이터 5 + 브리치 1 + 코어 1"
- **G1. 게이트 HP 30 → 20** (최대 HP도 20)
- **G2. 오거 관통**: 오거가 ICE가 있는 코어를 공격하면, ICE에 줄 피해(상성 적용 후)의 50%가 코어 본체로 관통하고 나머지가 ICE로 간다. 관통 피해는 E1 누적에 포함. [추정] B(코어 ×2)는 관통분에도 적용, 노드 배율 ×1.5는 미적용. 로그 "(G2 관통: ICE x / 코어 y)"
- **H. 숨은 금고** (`hiddenVaultsEnabled`, v0.5 측정 이후 구현 — 측정에 포함 안 됨)
  - 진영별 저장 소켓 4곳 = 기존 금고1·금고2 자리 + 바깥 릴레이1·릴레이3 자리 (**[기획 v0.3]** 확정). 화면·로그에서 이름은 "소켓1~4"
  - 구축 단계 왼쪽 패널 "금고 지정"에서 2곳을 고른다 (미선택 시 소켓1·소켓3 = 기존 금고 자리). 고른 곳은 금고(HP 20, 데이터 4), 나머지 2곳은 중계(HP 15, BW +2, 발사 지점). 그래서 금고 2 + 중계 3 구성은 그대로
  - 허니팟은 금고로 지정하지 않은 소켓에만 설치 가능
  - 상대 소켓은 정찰 전 모두 중계로 보이고 HP·데이터도 "?". 핑을 맞으면 진짜 금고와 허니팟 소켓 모두 같은 "금고 신호"(종류는 여전히 중계 표시). 프로그램이 직접 들어가거나 파괴·서든데스 안개 해제 시 공개 [추정]
  - 수동 확정(버튼·Space)은 금고 소켓을 정확히 2곳 골라야 가능 — 0·1곳이면 막히고 패널에 "확정 불가: … (현재 N곳)". 3번째 소켓을 누르면 가장 먼저 고른 곳이 빠지고 무엇이 빠졌는지 패널에 표시
  - 타이머 만료 자동 확정만 빈 자리를 기본 소켓(소켓1·소켓3, 이미 골랐으면 그다음 순서)으로 채우고 고른 곳은 유지. 안내 로그는 그 플레이어에게만 보임 (핫시트에서 상대 화면·가림 화면·공유 로그에 노출되지 않음)
  - AI: 시드로 6가지 소켓 조합 중 하나를 결정론적으로 선택(시드 없으면 기존 자리), 허니팟은 금고 아닌 소켓으로 옮김. 사이펀 목표는 드러난 금고 + 금고 신호가 잡힌 소켓(허니팟일 수 있음)

- **데이터 감속안 측정 (`../balance_results_v0.3.md`)**: 요청 3조합 모두 목표 미달. D1+D2 조합은 데이터 승리가 불가능해 82~100%가 20턴 시간 판정. A+B+C+D1+D2+D3가 요청 조합 중 최선(코어 피해 지표 3개 충족). 참고로 D1 없이 A+B+C+D2+D3가 평균 턴·시간 판정 목표를 충족. 공성형 AI 승률은 모든 조합에서 0~11%
- AI는 D 옵션(목표 점수·중립 상한)을 인지하지 않음
- **v0.8 측정 (`../balance_results_v0.8.md`)**: 하운드 5 CYC는 노이즈 수준의 변화만 냈다. 두 조합 모두 게이트 돌파 ≤T12, 기획 매치업 코어 승, 혼합 풀 데이터 승 목표를 충족하지 못했다. 공성형 첫 파도가 하운드에 전멸하는 비율은 5~7%였다. 첫 파도 오거의 가장 큰 손실 원인은 노출도 한계에 따른 철수(41%)다
- **v0.7 측정 (`../balance_results_v0.7.md`)**: 모든 목표를 충족한 조합 없음. V1이 켜지면 데이터 승리가 수학적으로 불가능하다 (중립 상한 4 + 금고 3×2 = 10 < 12). V2도 데이터 승 0~8%. AI 조기 공성은 평균 게이트 돌파를 T15.4 → T14.3으로만 당겼다 (목표 ≤T12 미달)
- **v0.6 측정 (`../balance_results_v0.6.md`)**: 두 풀 모두에서 3개 목표를 다 충족한 조합 없음. +C'가 공성형 39%, 시간 판정 5~8%로 가장 근접. 혼합 풀 데이터 승은 51~57%로 미달. 평균 게이트 돌파 턴은 T15~T18로 목표 T10에 못 미침. C'에서는 서든데스가 끝낸 판이 28~44%
- **v0.5 측정 (`../balance_results_v0.5.md`)**: 4개 조합 모두 기획 목표(공성형 ≥35%, 데이터 승 ≤45%, 시간 판정 ≤20%) 동시 충족 실패. +G1+G2가 최선(코어 승 18~23%, 기획 매치업 데이터 승 42%). 공성형 최대 15.6%(G2), G1 효과 작음, 시간 판정 24~42%
- **코어 브리치 데이터 측정 (`../balance_results_v0.4.md`)**: 기준선/E1/E2 모두 기획 목표(공성형 ≥35%, 데이터 승 ≤45%) 미달. 공성형은 0~4.4%. E1은 코어 피해를 코어 승리 대신 데이터 승리로 바꿔 지표가 오히려 나빠졌고, E2가 셋 중 가장 균형적. 공성형의 병목은 게이트·코어 ICE 돌파 속도(판당 코어 본체 피해 4~7)
- vs AI 매치는 매번 새 AI 시드를 쓰므로 같은 조작이라도 AI 행동이 판마다 다를 수 있다 (시뮬레이션 자체는 결정론적)
- 헤드리스 AI 대전에서 코어가 거의 깎이지 않음: 게이트 + 벌워크 + 하운드 수비가 강해 승부가 데이터 승리 또는 시간 판정으로 끝남 (시드 없는 AI 기준: 균형형 vs 균형형은 20턴 무승부, 돌격형 vs 균형형은 13턴 데이터 승리). 상성·HP 1차 튜닝이 필요함
- 중립 노드 데이터(0.5점/턴 × 3개)가 금고 탈취 대비 강할 수 있음
- AI는 단순 규칙형이라 허니팟·셰이드 운용이 서툴고, 남는 CYC를 상한에서 버리는 경우가 있음
- 모바일·좁은 화면 대응 없음 (1280×800 이상 기준)
